## Issues Found & Fixed

### [CRITICAL] `app/globals.css` — Font family never applied

**Line 25**

```css
/* Before (bug) */
font-family: Arial, Helvetica, sans-serif;

/* After (fix) */
font-family: var(--font-sans), Arial, Helvetica, sans-serif;
```

The Geist Sans font is loaded via Next.js font optimization in `layout.tsx` and registered as `--font-sans` in the `@theme` block, but the `body` rule hardcodes `Arial` instead of consuming that variable. The result is that Geist is downloaded by the browser but never rendered — every user sees Arial. Fixed by using `var(--font-sans)` with Arial as a fallback.

---

### [HIGH] `app/page.tsx` — External links missing `target` and `rel`

**Lines 21–34**

The two inline text links ("Templates" and "Learning center") pointed to external domains (vercel.com, nextjs.org) but lacked `target="_blank"` and `rel="noopener noreferrer"`. The four button-style links at the bottom of the same page correctly include both attributes.

**Issues:**
- **Inconsistency:** users expect external links to open in a new tab given the rest of the page's behaviour.
- **Tab-napping risk (if `target="_blank"` is ever added without `rel`):** without `rel="noopener"`, a newly opened page could access `window.opener` and redirect the parent tab.

Fixed by adding `target="_blank" rel="noopener noreferrer"` to both links.

### [HIGH] `next.config.ts` — No HTTP security headers

The configuration was empty, meaning the application served no security response headers.

Added the following headers to all routes:

| Header | Value |
|---|---|
| `X-Content-Type-Options` | `nosniff` — prevents MIME-type sniffing |
| `X-Frame-Options` | `SAMEORIGIN` — blocks clickjacking via iframes |
| `X-XSS-Protection` | `1; mode=block` — legacy XSS filter for older browsers |
| `Referrer-Policy` | `strict-origin-when-cross-origin` — limits referrer leakage |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` — disables unused browser APIs |

Note: A `Content-Security-Policy` header is recommended but requires per-project configuration based on actual asset sources. It should be added when the project's content requirements are defined.

### [MEDIUM] `package.json` — Missing `engines` field

No minimum Node.js version was declared. Next.js 16 requires Node.js 18.17.0 or later. Without an `engines` constraint, developers or CI systems running older Node versions will encounter obscure runtime failures.

Added:
```json
"engines": {
  "node": ">=18.17.0"
}
```

Line 5: outer `<div>` sets `min-h-screen bg-zinc-50 dark:bg-black`.
Line 6: inner `<main>` also sets `min-h-screen bg-white dark:bg-black`.

The inner element overrides the outer background entirely, making the outer div's background style dead code. Simplify by removing the outer wrapper or the redundant `min-h-screen` from the inner element.

### [LOW] `app/page.tsx` — Hardcoded hex colours in hover states

Lines 39: `hover:bg-[#383838] dark:hover:bg-[#ccc]`

These arbitrary Tailwind values bypass the design token system. If the brand palette changes, these colours will not update automatically. Prefer semantic Tailwind classes (e.g. `hover:bg-zinc-700`) or CSS custom properties defined in `globals.css`.
